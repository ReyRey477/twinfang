# TWINFANG

A character-action prototype that runs in the browser with Three.js. Everything is generated by code at load time: models, textures, animation and audio. There are no image, model or sound files.

You play a duelling automaton climbing a storm citadel. Fight down the machine nave, beat the Gatewarden in the gear hall, climb the winding stair, clear three sealed rooms on the upper level, then face the Stormvane on the roof.

## Play

Open `twinfang.html` in a desktop browser (needs an internet connection for Three.js and fonts). The build number is in the bottom right corner of the title screen.

Add `?q=low` to the address if it runs slowly (half-size textures, no ambient occlusion, no MSAA), or `?q=high` for the sharpest image.

## Controls

| Input | Action |
| --- | --- |
| W A S D, mouse | Move, camera |
| 1 2 3, F, mouse wheel | Switch weapon set (works mid-combo) |
| Left click / J | Attack chain |
| Right click / K | Twin Fangs: launcher (hold to follow). Blade & Pistol: fire, hold for auto-fire. Great Maul: hold to charge a smash |
| E | Twin Fangs and Great Maul: rush thrust. Blade & Pistol: launcher |
| Space | Jump, double jump |
| Shift / L | Dodge; dodge at the last instant to slow time |
| Q | Lock-on |
| R | Retry from the last checkpoint after a defeat; restart after the results screen |

A gamepad also works.

## Weapon sets

- **Twin Fangs** – fast four-hit chain, a pause combo (slash, slash, wait for the glint, slash), launcher and plunge.
- **Blade & Pistol** – the third sword hit launches. The pistol does little damage but interrupts attacking enemies, keeps airborne enemies up, pops orbs and keeps the combo alive.
- **Great Maul** – slow, wide sweeps. A fully charged smash breaks armour on big enemies and bosses. The air attack bounces everything nearby into the air.

## Enemies

- **Husk** – basic melee. Sometimes chains a second, faster slash straight after the first.
- **Brute** – armoured; only heavy hits move it until its armour breaks. Below about half health its slam also throws a shockwave: jump it or dodge through.
- **Stalker** – drops from the ceiling, then dashes through you, and sometimes turns and dashes back.
- **Lantern** – hovers out of reach, fires slow orbs and shields one ally with a tether. Slash an orb back to stun it; pistol shots drag it lower.

Every attack is announced by a flare and a rising whine before it lands, including the follow-ups.

## Source layout

The game is authored as parts in `src/` and concatenated into the single file `twinfang.html`:

```bash
python build.py
```

Edit the parts, not `twinfang.html`.

| Part | What it holds |
| --- | --- |
| `02-audio` | Sound engine. Each sound is a recipe that layers noise, low thumps and short dense "clanks" into a buffer (several variants each, no ringing tones); two generated reverbs, ambience beds, the combat music sequencer |
| `03-renderer` | Render pipeline: HDR scene, ambient occlusion, bloom, lens, ACES tone map and grade |
| `04-textures` | Material system. A shader per material bakes albedo, normal, roughness and metalness maps on the GPU (painted `shell` for the hero, bare `armor` for foes) |
| `05-world` | The level: walkable `AREAS` (the only thing collision looks at) and the kit that dresses them |
| `06-fx`, `06b-fx2` | Particles, trails, shockwaves, wreckage |
| `07-rig` | Character rig, pose format, IK, the grip and wrist solver, and the models of the hero and foes, built from lofted shells (`loft`) |
| `08-clips`, `08b-clips2` | Animation clips (keyframed poses) and `STANCE`: how the hero holds each weapon set standing, running and airborne |
| `10-data` | Character materials, moves, encounters |
| `11*` | Enemies and the two bosses |
| `12-player`, `13-camera`, `14-game` | Player, camera, game loop |
| `15-harness` | Developer harness (below) |

## Developer harness

These work on the normal build; none of them run in ordinary play.

| Address option | What it does |
| --- | --- |
| `?show=hero` (or `husk`, `brute`, `stalker`, `lantern`, `warden`, `storm`, `mats`, `all`) | One subject, or the whole cast, on a lit stage with an orbiting camera. Extra options: `&a=30` fixed angle, `&d=2.5` distance, `&h=1` height, `&clip=run` animation, `&t=0.2` freeze at a time, `&set=1` weapon set (hero) |
| `?tp=x,y,z,yaw` | Start at that spot |
| `?cam=x,y,z,tx,ty,tz` | Fixed camera, HUD hidden |
| `?bench` | Flies a fixed path through the level and prints average, median and worst-case frame times |
| `?nan` | Shows a live count of invalid pixels (see the shader rule below) |
| `?debug` | Keeps the canvas readable for screenshots |

From the console: `HX.show(kind, opts)`, `HX.tp(...)`, `HX.view(...)`, `HX.stats()` (draw calls, triangles, error count), `HX.nanCheck()` (counts invalid pixels in the current view; see the note below), `window.__errors`, and `window.G`, `window.cam`, `window.step(n, dt)` for stepping the simulation by hand. `devtest.js` is a console harness with a random-input bot that plays through every encounter.

**Shader rule: never let an invalid number reach the screen.** A single NaN or infinite pixel is blurred by bloom into a black block hundreds of pixels wide. It happens most easily with `pow()` of an interpolated value: at polygon edges that value can dip below zero, and Direct3D (Chrome, Brave and Edge on Windows) returns NaN for a negative base, while other renderers quietly do not. Clamp before `pow`, `sqrt` and `normalize`. Lit materials and the frame as a whole are also guarded (`GUARD` in `04-textures`, the pass before bloom in `03-renderer`), so a mistake shows up as one dark pixel instead of a blacked-out screen.

**How weapons are held.** A pose says where each grip is and where the blade points. The rig then places the wrist a palm's length behind the grip, on the side the forearm comes from, and builds the hand round the grip axis, so fingers always wrap the hilt (or the pistol's handle, or the maul's shaft) whatever the swing is doing. With the maul the right hand leads and the left slides along the shaft to wherever it can reach.

`tools/` holds the headless test runner used to build this version (screenshots of any scene, showcase or hero pose, a grip-stability check, an audio lab that renders the sound to files and spectrograms, and a full bot playthrough). See `tools/README.md`.
