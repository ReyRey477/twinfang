## What the project is

Twinfang is a Devil May Cry-style character-action prototype in the browser: Three.js r160 from a CDN, one built file `twinfang.html`, authored as parts in `src/` and concatenated by `python build.py`. Everything is generated by code at load: models, textures, animation, audio. No asset files.

Scope: a corridor with two fights, the Gatewarden boss in a hall, a winding stair, three sealed rooms, the Stormvane boss on the roof. Three weapon sets (Twin Fangs, Blade & Pistol, Great Maul), four enemy types (Husk, Brute, Stalker, Lantern).

The owner designs and playtests; Claude writes the code. They prefer a plain summary of what changed and what was not checked over a description of effort. Their reference images for the characters are in `references/` (git-ignored).

## What the owner asked for in this session, and what was done

They said the game "looks better than before, but is still lacking", that the player "holds weapons in a real awkward way", and that "the whole sounds are awful", especially "the bell like sounds".

## How it was verified, and the limits of that

On this PC, real GPU, build `.4`:
- `s_bot.mjs`: the bot completes all seven encounters with zero errors. It refills its own health and drains boss health on a timer, so this proves the game does not break, not that it is fair or fun.
- `s_nan.mjs` and `s_ctx.mjs` (the same count with the Lantern and Stormvane in view): zero invalid pixels in every view, on Direct3D. This is the first real-hardware evidence for the old black-block bug (open problem 1 of the previous handoff); the owner has still not confirmed it by eye.
- `s_perf.mjs` at 1920x1080: 4 to 7 ms per frame everywhere (about 140 to 230 fps of headroom), worst in the corridor with six enemies.
- `s_grip.mjs`: no hand or blade turns more than about 0.75 rad in one 1/180 s step; what remains is authored strike speed.
- `s_audio.mjs`: the whole bank synthesises without bad samples; `audio_view.py` finds no narrow spectral peak above 250 Hz that holds longer than 48 ms (the old bank: up to 1180 ms).
- Screenshots of every character, every hero stance and attack with each weapon set, and the pistol aimed in six directions were reviewed.

Never verified:
- **How anything sounds.** The sound was measured and its spectrograms read, never heard. Musical taste, mix balance by ear and "feel" are unjudged. This needs the owner's ears first.
- **Motion.** Poses were checked as stills at chosen times, not as moving animation.
- **Combat feel and difficulty.** Unchanged by this session, still unreviewed.
- **The owner's own browser** (Brave). The tools use Edge; both are Chromium on the same Direct3D path.

## Open problems, in priority order

1. **Owner feedback on the three things they asked for**: the holds, the sound, the look against their references.
2. **Animation pass.** Player and boss clips are still the old keyframes, now with better holds. Anticipation and recovery poses are the obvious next step once the owner has played.
3. **Model detail.** The hero is clean but plain at close range (the chest yoke is one smooth piece; the references show more exposed mechanism). On the dark roof the grounded Stormvane is mostly a shape carried by its lights, and its wing spars are plain tubes up close. At distance in a dark room the Lantern is slender; its core, halo and horn rings carry it.
4. **Enemy animation does not use the new hand system.** Foes still mount their blades on a free wrist (`gripD` is 0 for them), which suits machines but is less convincing than the hero's hands.

## Working rules learned the hard way

- **Bump `BUILD` in `src/01-util.js` with every delivered change**, and tell the owner which number to look for.
- **Rebuild after every edit** (`python build.py`). The owner opens `twinfang.html`, not `src/`.
- **Clamp before `pow`, `sqrt`, `normalize` and division** in every shader. See the shader rule in `README.md`.
- **A pass on the software renderer is not a pass on Direct3D.** On this PC the tools use the real GPU; say which one a result came from.
- **Do not change `AREAS`, hit timings or damage numbers casually.** They were tuned by play before this rebuild.
- **After a scripted edit, check the file's structure.** A splice with an ambiguous marker duplicated half of `07-rig.js` in this session, and because a later method definition silently replaces an earlier one, the game ran without errors on the old code. `grep -c "apply(dt){" src/07-rig.js` must print 1.
- **No bells.** Any new sound must pass `audio_view.py` with `ring` under about 60 ms.
- Line endings: the repository stores LF; the Windows checkout has CRLF (`core.autocrlf`). `build.py` reads either and writes LF.

## Useful commands

```bash
python build.py                                   # src/ -> twinfang.html
node tools/run.mjs tools/s_bot.mjs                # must end: RUN COMPLETE, errors: 0
node tools/run.mjs tools/s_nan.mjs                # must end: NAN CHECK PASSED
node tools/run.mjs tools/s_audio.mjs              # must end: AUDIO CHECK PASSED
node tools/run.mjs tools/s_grip.mjs               # lists any hand or blade that snaps
node tools/run.mjs tools/s_perf.mjs --w 1920 --h 1080
node tools/run.mjs tools/s_poses.mjs --w 420 --h 420 && python tools/sheet.py pose 6
node tools/run.mjs tools/s_show.mjs --w 1500 --h 800 --kinds "all:8:d=8;h=2.3"       # the whole cast
node tools/run.mjs tools/s_states.mjs --w 560 --h 520 && python tools/sheet.py state 4   # Lantern and Stormvane in each state
node tools/audio_lab.mjs && python tools/audio_view.py
```
